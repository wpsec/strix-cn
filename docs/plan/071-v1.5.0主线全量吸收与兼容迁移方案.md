# 071 v1.5.0 主线全量吸收与兼容迁移方案

## 摘要

本轮同步以 **上游 `v1.5.0` 标签** 为唯一基线。`v1.5.0` 发布时间为 **2026-08-07**，本次落地时间为 **2026-08-10**。目标是：

- 完整吸收 `v1.5.0` 的功能、修复和运行时改动
- 完整保留 `strix-cn` 的既有中文体验、Burp / Caido 工作流和兼容性适配
- 以“上游新架构为基底，移植本地能力”为原则解决冲突
- 在文档中沉淀可复用的下次同步 SOP

## 为什么锁定 `v1.5.0` 而不是 `upstream/main`

- `v1.5.0` 是已经发布的稳定切片，功能边界明确，便于做一次可验证、可回溯的同步
- `upstream/main` 在同步当天仍可能持续变化，会把发布后尚未稳定的新提交一起带入，增加冲突面和回归面
- `strix-cn` 需要兼顾中文体验、Burp 工作流和受限网络兼容；锁定 tag 能先稳住架构基线，再按轮次吸收后续主线变化

## 合并基线与分支策略

- 同步分支：`sync/upstream-v1.5.0-full-merge`
- 合并对象：上游 `v1.5.0` 对应提交，不直接追 `upstream/main`
- 合并提交信息固定为：

```text
chore(core): 合并上游 v1.5.0 并迁移到新 TUI 架构
```

## 冲突分层结果

### 1. CLI / TUI

- 最终裁决：以上游 Go / Bubble Tea TUI 为唯一主线
- 保留方式：
  - 中文默认文案与关键状态提示继续保留
  - Burp / Caido 被动扫描工作流迁回新 TUI / CLI
  - 旧常用参数和入口保持兼容，例如 `strix` 主入口、`--burp-port`、`--mount`
- 不保留项：
  - 旧 Python Textual TUI 不再作为长期主实现

### 2. Runtime / Proxy

- 最终裁决：以上游 mount 模式和生命周期修复为准
- 直接沿用：
  - 本地目录挂载策略
  - agent 生命周期与等待 / 恢复语义修复
  - stream 卡死防护、tool-call 队列修复
  - Docker run-id 标记与清理逻辑
- 迁移保留：
  - Burp / Caido 端口、上游代理、功能批次分发、作用域控制

### 3. Reporting

- 最终裁决：以上游新增字段和约束为准，中文交付习惯不回退
- 直接沿用：
  - dependency metadata、manifest_path、reachability 记录
  - 严重性校准与 dedupe 相关修复
- 迁移保留：
  - 中文报告标题、章节、修复成本、交付版整合报告结构

### 4. 文档

- 最终裁决：保留中文主文档，同时补齐上游 `v1.5.0` 新能力说明
- 直接沿用：
  - 中文 README、CLI 参考、配置说明、贡献指南
- 迁移保留：
  - API spec / Postman、Viewer、ChatGPT 登录、编码代理技能接入、Go sidecar 打包说明

### 5. 静态资源

- 最终裁决：不手工拼接 bundle 文件名，重新构建 viewer 静态产物
- 结果：
  - 使用当前前端源码重新执行构建
  - `strix/interface/viewer/static/index.html` 与 `assets/` 产物同步更新

### 6. 依赖与构建

- 最终裁决：以 `v1.5.0` 依赖基线为主，保留 `strix-cn` 必要兼容依赖
- 关键结果：
  - sandbox 默认镜像统一升级到 `1.3.0`
  - 移除旧 Textual 运行时痕迹
  - 保留 `socksio` 以维持 SOCKS 代理兼容

## “保上游实现”与“保本地能力”的取舍方式

### 直接沿用上游

- Go / Bubble Tea TUI 架构
- local targets mount 模式
- API spec / Postman 目标支持
- reporting 与 dedupe 增强
- LLM 额外 headers、禁用 streaming、structured refusal 展示

### 通过迁移保留本地能力

- 中文 CLI / TUI / 报告输出
- Burp / Caido 被动扫描和功能批次工作流
- 本地模型、兼容网关、SOCKS / 代理环境提示
- 本地源码工作区挂载和常用命令路径

## 下次同步固定 SOP

1. 先确认 release tag，不直接追 `upstream/main`
2. 先在临时分支做无污染合并预演
3. 先看 `modify/delete`、`rename/rename` 和架构级冲突
4. 先解架构冲突，再解文案冲突
5. 先恢复运行链和测试，再改 README / docs
6. viewer 静态资源冲突优先重新构建，不手工改 bundle 文件名
7. 纯上游 tag 合并后、Runtime / TUI 冲突解完后、回 `main` 前，都必须执行 `./scripts/merge-guard.sh`
8. 合并完成后补充本轮热点文件、裁决记录和 `docs/plan/091-主线同步门禁与能力契约.md` 中的能力契约矩阵
