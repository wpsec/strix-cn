# 091 主线同步门禁与能力契约

## 摘要

`071` 解决的是“按什么原则合并”，本文件解决的是“什么情况下不允许合并完成”。目标是把 `strix-cn` 的本地价值从文档描述改成可执行门禁，避免下次同步上游后只剩壳子、功能回退靠人肉发现。

本门禁采用三层结构：

- 能力契约：每条本地能力必须写清触发条件、可见结果、失败症状
- 定向测试：每条高风险能力至少有一条 focused guard test
- 固定门禁命令：合并过程中必须执行 `./scripts/merge-guard.sh`

门禁测试必须保持 focused。不要把与“本地能力保留”无关、但恰好位于同一测试文件中的广泛回归测试整包塞进来，否则门禁会被无关漂移打红，失去同步定位价值。

## 为什么 `071` 还不够

- `071` 说明了冲突裁决原则，但不会在回退时自动报警
- “保留 Burp / Caido 工作流”这类表述太宽，不能直接转换成验收
- 上游同步后的空壳问题，往往不是功能完全消失，而是交互、提示、约束或状态切换局部断裂

换句话说：只有文档，没有测试和门禁，下一次仍然会重复同类问题。

## Merge Guard 组成

### 1. 能力契约

能力契约必须回答四个问题：

- 触发条件是什么
- 用户应该看到什么
- 失败时会表现成什么症状
- 哪些热点文件最可能导致它回退

### 2. 定向测试

- Python focused tests：守 scope、prompt、runtime、CLI、本地化、被动代理控制链路
- Go focused tests：守 TUI 状态栏、焦点、Viewer 点击命中、被动代理阶段文案
- 新增高层合同集：`tests/test_merge_guard_contracts.py`

### 3. 固定门禁命令

```bash
./scripts/merge-guard.sh
```

这条命令应该在同步流程中至少运行四次：

1. 纯上游 tag 合并后，尚未补本地兼容时
2. Runtime / Proxy 冲突解决后
3. TUI / Prompt / 交互冲突解决后
4. 合并回 `main` 之前

## 失败处理规则

门禁失败时，禁止先改 README / docs 掩盖问题，必须先完成下面动作：

1. 先判断失败属于哪一层：
   - `scope/prompt`
   - `runtime/proxy`
   - `tui/interaction`
2. 只看该层的热点文件，不要在全仓库漫无目的 diff
3. 先修能力契约，再修文案
4. 门禁重新通过后，才允许更新同步文档

## 下次同步时的强制动作

在 `071` 的 SOP 基础上，再加四条硬动作：

1. 先创建“纯上游合并提交”，不要一边合并一边掺本地补丁
2. 纯上游合并后立刻跑一次 `./scripts/merge-guard.sh`
3. 所有失败项必须逐条挂到本文件的能力契约矩阵中定位
4. 每新增一个 `strix-cn` 独有能力，必须同步补：
   - 一条能力契约
   - 至少一条 focused test
   - 至少一个热点文件清单

## 扩展规则

- 如果某个本地能力已经连续两次在同步后回退，下一轮必须把它从“提示约束”升级到“代码层硬限制”
- 如果某个能力没有 focused test，就不允许写进“必须保留能力”清单
- 如果某个测试失败与本地能力契约无关，就不要直接把整文件纳入门禁，而应收敛到最小节点集
- 如果某条门禁命令经常被跳过，就把它放进 CI 或本地 pre-merge checklist，而不是继续依赖口头流程

## 被动代理 Endpoint 覆盖闭环

被动代理模式中的“当前功能点”是用户工作流概念，不得再由最新一条请求推断为唯一测试范围。一次发送“开始测试”前可能已经采集多个页面或 API，因此每轮按以下规则执行：

1. 代理采集器按 `METHOD + host + path` 汇总本轮动态 endpoint，并排除常见前端静态资源。
2. 控制器用上轮结束时间与本轮开始时间冻结请求范围，同时计算 endpoint 请求计数增量。
3. Root 必须把完整冻结清单交给攻击面分析专家，不能只选择最后访问的页面。
4. 非映射测试专家的 task 必须原样包含所负责的 endpoint，`create_agent` 会自动登记认领关系。
5. 确认无需主动测试的 endpoint，必须调用 `mark_endpoint_not_applicable` 写明具体理由。
6. 清单仍有未认领项且没有运行中的子 agent 时，`wait_for_agents`、`respond_to_user` 与 `finish_scan` 必须拒绝进入完成态。

该闭环只要求 endpoint 有明确责任人，不要求一个 endpoint 对应一个独立专家。相关 endpoint 可以由同一专家批量覆盖，但任务范围必须显式可审计。
