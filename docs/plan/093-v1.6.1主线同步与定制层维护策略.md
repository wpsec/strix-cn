# 093 `v1.6.1` 主线同步与定制层维护策略

## 摘要

本文档记录截至 `2026-09-04` 的上游同步判断与执行留痕。本轮与 `092` 的窄修复同步不同，是架构级大版本吸收（`v1.5.3 -> v1.6.1`），采用 `071` 的整包 merge + 分层人工整合路线，并以 `091` 的 merge-guard 作为唯一放行门禁。

核心结论：

- 本轮必须整包 merge（71 提交、228 文件），cherry-pick 不现实
- 既有能力（Burp 被动扫描、国内网关、中文体验、本地 Viewer）经门禁验证全部保留
- 上游有三处与 fork 架构正面冲突，本轮做了明确的"主动让位"决策，全部记录在本文

## 合入后首个真机发现（已修，属 Anthropic 协议适配能力）

真实 token-plan 扫描中，侦察子 agent 提交长中文 note 时整轮失败：`create_note` 的
tool_use 参数被截断成非法 JSON（`Unterminated string`）。根因：Anthropic Messages
协议必填 `max_tokens`，`qwen3.8-flash` 不在 LiteLLM 能力表，回退默认 4096；
OpenAI 兼容路径不触发。修复：`_configure_anthropic_max_tokens_default()` 在
LiteLLM 首次 import 前把该回退值提到 8192（同名 env 可覆盖），并补
`test_anthropic_max_tokens_default_respects_operator_env` 与 `anthropic.mdx` 提示。
该 env 在 `litellm.constants` import 时冻结，因此必须由 Strix 内部先行 setdefault。

同轮第二发现：`anthropic/qwen3.8-max` 等被前缀改写后，`context_budget` 查不到窗口
（表里键在 `dashscope/` 下），compaction 退到 200k 兜底——172M input tokens 那轮的
放大器。修复：`_suffix_match` 按裸 slug 跨 provider 多数匹配（真机验证 qwen3.8-max
991808/131072、kimi-k2.7-code 262144 恢复）；pricing 侧本已有后缀回退不受影响。
完全未映射的新模型（`qwen3.8-flash`）仍需兜底或模型画像表（待办 B）。
