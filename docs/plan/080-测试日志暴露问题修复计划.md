# 080 测试日志暴露问题修复计划

## 目标

针对 `pentest_20260730_164947_676166` 暴露出的运行问题，确保：

- LLM 配额或模型错误不会让某个子 agent 静默丢失覆盖范围；
- TUI 能区分“等待下一功能点”和“等待子 agent”，不再因代理图读取超时刷屏；
- Caido HTTPQL 错误能返回可行动的结构化信息，避免只留下通用异常；
- Caido replay 传输异常保持有限重试，并明确失败原因；
- 关键路径有回归测试，后续改动不会重新引入相同问题。

- `strix/interface/tui/app.py`
- `strix/core/execution.py`
- `strix/tools/proxy/tools.py`
- `strix/tools/proxy/caido_api.py`
- 现有执行、TUI 和代理客户端测试

## 实施步骤

1. 补强 terminal child 通知，向父 agent 传递失败原因和下一步建议。
2. 调整 Burp 功能点工作流：失败或崩溃的测试专家不能被当作“已覆盖”，需要触发补派提醒。
3. 优化 TUI 代理图读取：优先使用已同步的本地快照，异步读取超时时不输出重复 traceback。
4. 优化等待状态文案，明确当前功能点完成后是在等待下一批流量，而不是等待 subagent。
5. 对 Caido HTTPQL 错误进行分类，返回 `error_type`、`retryable` 和修复提示。
6. 保持 replay 传输错误的单次刷新重试，并增加结构化错误信息和测试覆盖。
7. 为配额失败、terminal 通知、失败专家补派、TUI 快照和 HTTPQL 错误补充回归测试。
8. 运行定向测试和全量相关测试，记录尚需外部处理的 LLM 配额、Caido 权限与网络问题。

## 非目标

- 不在代码中硬编码 API Key、Token、密码或测试凭据。
- 不自动提升 Caido 权限、不修改外部代理配置、不重放真实业务请求。
- 不把临时提高 LLM 配额伪装成代码修复。

## 验收条件

- 子 agent 以 `failed`、`crashed` 或 `stopped` 结束时，父 agent 能收到包含原因的消息。
- 功能点工作流对失败专家触发一次补派/覆盖提醒，正常完成的专家不触发重复提醒。
- TUI 代理图读取不再因固定两秒跨线程等待产生高频 traceback；已有快照可继续驱动根 agent 选择。
- HTTPQL 失败结果包含稳定的错误类别和可执行提示，其他 Caido 异常行为不被改变。
- 所有新增行为有自动化测试，定向测试通过。

## 实施结果

- `execution`：terminal child 通知增加脱敏后的失败类别和处理建议；`insufficient_quota`、限流、网络错误和 turn 上限不再以空白状态传递给父 agent。
- `tui`：优先使用已同步的 live agent 快照选择根 agent；代理图异步读取超时时降低日志噪声；失败、崩溃或停止的专家不再被视为已覆盖，并会触发补派提示。
- `proxy`：Caido HTTPQL、replay transport、超时和通用异常统一返回 `error_type`、`retryable`、`hint`，保留 replay 的单次刷新重试。
- `reporting`：CWE-79 必须提供浏览器/DOM/回调等实际执行证据，且 DOM 中出现未编码的 HTML 节点不等于脚本执行；DOM marker 必须是 payload 脚本设置或回调确认的唯一标记。CWE-89 必须提供可控 oracle；单纯响应回显或通用 4xx/5xx 不再允许创建动态漏洞报告。
- `runtime`：sandbox 创建、端口预检、端口解析和 Caido 启动任一阶段失败时统一回收部分创建的 session；Docker 容器写入 `scan_id` 管理标签，进程缓存丢失后可按标签做幂等回收。
- 新增/更新执行、TUI、工作流和代理客户端回归测试。

## 误报样本复核

- `pentest_20260731_144506_235818` 中的 `vuln-0004`、`vuln-0005`、`vuln-0011`、`vuln-0014` 只有 JSON 回显和“若前端使用不安全 sink 则可能执行”的前提，没有浏览器执行、DOM marker、dialog、console 或回调证据，因此应视为未确认的输出编码观察项，不应标记为已确认 XSS。
- 最新复核中的 `updateById` payload 虽然在浏览器 DOM 中出现为 `<img>` 节点，但当前没有 dialog、console marker、唯一 DOM marker 或 callback 的执行结果；该证据只能说明 HTML 注入/未编码观察，不能作为已确认 XSS。
- `vuln-0009` 只有正常请求 200、特殊字符请求 500 的差异，没有布尔/时间 oracle、数据库错误/元数据、UNION 结果或 OAST 回调，因此不能确认 SQL 注入。
- 上述历史产物保留不变；新的报告入口会在落盘前拒绝同类证据不足的报告。
