`strix-cn` 是面向中文用户的持续维护分支。这里的贡献会优先围绕国内模型接入、Burp 工作流兼容、受限网络与跨平台环境适配，以及中文文档和中文报告体验展开。

## 开发环境准备

### 前置要求

- Python 3.12+
- Go 1.24.x（仅在开发或打包新的 Bubble Tea TUI sidecar 时需要）
- Docker（已启动）
- [uv](https://docs.astral.sh/uv/)
- Git

### 本地开发

<Steps>
  <Step title="克隆仓库">
    ```bash
    git clone https://github.com/usestrix/strix.git
    cd strix
    ```
  </Step>
  <Step title="安装依赖">
    ```bash
    make setup-dev

    # 或手动执行
    uv sync
    uv run pre-commit install
    ```
  </Step>
  <Step title="配置模型">
    ```bash
    export STRIX_LLM="openai/your-compatible-model"
    export LLM_API_KEY="your-api-key"
    export LLM_API_BASE="https://your-gateway.example/v1"
    ```
  </Step>
  <Step title="运行 Strix">
    ```bash
    uv run strix --target https://example.com
    ```
  </Step>
</Steps>

## 贡献 Skills

Skills 是用于增强代理能力的专业知识包，存放在 `strix/skills/` 目录下。

1. 选择合适的分类目录。
2. 创建带有 YAML frontmatter（`name` 与 `description`）的 `.md` 文件。
3. 提供实战示例，例如 payload、命令或测试用例。
4. 补充验证方法，说明如何确认发现结果。
5. 通过 PR 提交。

## 贡献代码

### Pull Request 流程

1. 先创建 Issue，描述问题或需求。
2. Fork 并创建分支；如果是同步上游能力，请说明适配边界。
3. 完成修改，遵循现有代码风格。
4. 编写或更新测试，确保新功能和修复有覆盖。
5. 运行检查，`make check-all` 应通过。
6. 提交 PR，并附上背景说明。

### 代码风格

- 遵循 PEP 8，单行长度不超过 100。
- 所有函数都应带类型标注。
- 公共方法应有 docstring。
- 保持函数简洁、职责单一。
- 变量命名应清晰可读。

## Viewer 构建

`strix view` 使用一个预构建的本地 Web UI。源码位于 `strix/interface/viewer/frontend/`，构建产物提交在 `strix/interface/viewer/static/` 并随包发布。

如果你修改了 `viewer/frontend/` 下的内容，请重新构建并一并提交：

```bash
make viewer
```

等价命令：

```bash
cd strix/interface/viewer/frontend
npm run build
```

## 打包说明

可编辑安装不要求提前构建 sidecar；开发模式会直接从源码运行 Go TUI。

正式 wheel 会强制打包与当前版本匹配的 Go sidecar，并且是平台相关的：

```bash
make wheel
```

构建钩子 `scripts/tui_sidecar_hook.py` 会编译 sidecar、嵌入为 `strix/bin/strix-tui`，并写入当前平台 tag。`scripts/build.sh` 与 `strix.spec` 也依赖同一套 sidecar 产物。
